# SceneForge 多人协作产品规划

> 文档状态：规划稿，不代表当前版本已实现
> 更新日期：2026-07-31
> 当前产品：面向个人创作者，不提供多人账号、外部审核链接、成员权限或协作通知

## 1. 决策背景

SceneForge 当前最需要证明的不是团队管理能力，而是个人创作者能否稳定完成一条效果好的视频。多人协作会引入账号、项目隔离、权限、通知、审计、计费归属和数据迁移等系统性复杂度；在生成效果、首次成片成功率和个人留存尚未稳定前提前实现，会分散产品和工程资源。

因此当前版本已移除临时外部审核链接、访客审核页、多管理令牌和外部意见收件箱。个人版继续保留内部阶段审核、逐镜批注、版本对比、局部返工和恢复能力，这些是未来协作功能的数据基础，但不等同于多人协作。

## 2. 重新立项条件

多人协作只有同时满足以下条件才进入开发：

- 个人版首次成片成功率达到稳定目标，并连续四周没有明显下降。
- 至少 30% 的活跃用户在 30 天内完成第二个项目。
- 用户访谈中，多人审核或任务交接进入前三位高频阻塞问题。
- 至少 10 个真实团队愿意参与封闭测试，并明确现有分享方式无法满足需求。
- 平台已具备项目级成本、生成事实、版本和审计事件的稳定数据结构。

未满足上述条件时，只收集需求，不新增协作入口。

## 3. 目标用户与核心任务

### 3.1 目标用户

- 两到十人的短视频创作小组。
- 编剧、导演、剪辑或运营由不同成员承担的工作室。
- 需要外部审核，但不需要复杂企业采购和组织管理的内容团队。

### 3.2 核心任务

- 邀请成员进入一个项目，而不是共享后台令牌。
- 明确谁可以查看、编辑、生成、批准、发布和管理费用。
- 评论必须绑定具体项目、阶段、镜头、产物版本和可选时间码。
- 修改意见可以转成待办，并追踪处理中、已解决和重新打开状态。
- 任何会触发额外生成费用的操作都能追溯到具体成员。
- 外部查看者只能访问被分享的项目和媒体，不能读取模型密钥或其他项目。

## 4. 产品原则

- **个人版优先**：协作功能不得降低个人创作入口的简洁度。
- **项目隔离**：所有读取和写入都必须先验证项目成员关系。
- **最小权限**：默认只授予完成任务所需的最低权限。
- **版本绑定**：评论、批准和返工结论必须绑定具体产物版本。
- **费用明确**：触发生成前展示预计费用，并记录发起人和批准人。
- **异步优先**：先解决评论、审核和交接，不做实时光标或多人同时编辑。
- **可关闭**：个人用户看不到团队导航、成员设置和协作通知。

## 5. 首期范围

### 5.1 账号与工作区

- 邮箱或第三方登录。
- 个人工作区和团队工作区分离。
- 团队成员邀请、接受、移除和退出。
- 每个项目只能属于一个工作区。

### 5.2 权限角色

| 角色 | 查看 | 评论 | 编辑内容 | 触发生成 | 审核通过 | 发布 | 管理成员与费用 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 所有者 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 编辑者 | 是 | 是 | 是 | 是 | 否 | 否 | 否 |
| 审核者 | 是 | 是 | 否 | 否 | 是 | 否 | 否 |
| 查看者 | 是 | 否 | 否 | 否 | 否 | 否 | 否 |

首期不允许自定义角色，避免权限组合失控。

### 5.3 评论与审核

- 项目、剧本、分镜、镜头和成片五种评论对象。
- 镜头评论可绑定视频版本和时间码。
- 评论支持待处理、处理中、已解决和重新打开。
- 审核结论支持通过和修改后再审。
- 新版本生成后，旧版本结论保留但自动标记为历史结论。

### 5.4 通知与待办

- 站内待办为主，邮件通知为辅。
- 仅通知被提及成员、负责人和项目所有者。
- 支持按项目汇总，避免每条评论单独轰炸。
- 生成失败、等待审核、费用超限和任务完成属于高优先级通知。

### 5.5 外部审核

- 外部审核链接必须从项目权限体系派生，不能成为绕过账号体系的第二套权限系统。
- 链接限定项目、版本、媒体范围、有效期和操作权限。
- 服务端只保存令牌摘要，链接可立即撤销。
- 外部意见进入统一评论系统，不单独维护一套反馈账本。

## 6. 明确不做

- 多人实时共同编辑剧本或时间线。
- 实时光标、在线状态和语音会议。
- 完整企业组织架构、审批流设计器和自定义权限矩阵。
- 复杂客户关系管理、合同、发票和回款管理。
- 用共享后台令牌模拟成员账号。
- 评论自动触发付费生成；必须由有权限的成员确认。

## 7. 信息架构

```text
工作区
  ├─ 项目列表
  ├─ 成员与角色
  ├─ 用量与费用
  └─ 项目
      ├─ 创作流程
      ├─ 镜头与版本
      ├─ 评论与待办
      ├─ 审核记录
      └─ 发布记录
```

个人工作区默认隐藏“成员与角色”，项目创作界面保持与当前个人版一致。

## 8. 核心数据模型

```text
User
Workspace
WorkspaceMember(user_id, workspace_id, role)
Project(workspace_id, owner_id)
ProjectMember(project_id, user_id, role)
ArtifactVersion(project_id, scene_id, shot_id, version_id)
Comment(target_type, target_id, version_id, timecode, status)
ReviewDecision(target_id, version_id, decision, reviewer_id)
Task(comment_id, assignee_id, status, due_at)
AuditEvent(actor_id, project_id, action, cost_delta, created_at)
Invitation(workspace_id, email, role, expires_at)
```

所有业务表必须携带工作区或项目归属，服务层禁止通过客户端传入的工作区标识直接授权。

## 9. 安全与合规要求

- 密码和登录交给成熟身份服务或经过审计的认证库。
- 数据库查询默认注入工作区和项目范围。
- 媒体使用短期签名 URL，不暴露磁盘真实路径。
- 邀请和外部链接具有有效期、用途限制、撤销状态和访问审计。
- 模型密钥只允许所有者或被授权管理员管理，接口永不返回明文。
- 删除成员后立即终止其会话和媒体访问。
- 权限和隔离测试必须覆盖横向越权、令牌重放、过期、撤销和路径穿越。

## 10. 分阶段实施

### 阶段 0：需求验证

- 访谈真实团队，收集当前交接方式和失败案例。
- 用只读原型验证角色、评论和待办信息架构。
- 明确付费意愿和团队席位模型。

### 阶段 1：身份与隔离

- 账号、工作区、项目成员、固定角色。
- 项目级授权中间件和数据库迁移。
- 权限矩阵、审计日志和安全测试。

### 阶段 2：异步评论

- 版本和时间码评论。
- 评论状态、负责人、提及和站内待办。
- 项目活动时间线。

### 阶段 3：审核与费用控制

- 阶段审核结论。
- 返工前费用预览和生成权限。
- 费用归属、月度用量和预算阈值。

### 阶段 4：受限外部审核

- 项目级受限分享。
- 短期媒体访问和审核表单。
- 邮件通知、到期和撤销。

每个阶段独立验收，上一阶段的权限和隔离未通过安全测试时不得进入下一阶段。

## 11. 成功指标

| 指标 | 首期目标 |
|---|---:|
| 团队邀请接受率 | ≥ 70% |
| 评论被处理比例 | ≥ 80% |
| 审核平均往返次数 | 较线下沟通下降 30% |
| 因版本不一致产生的无效返工 | 下降 50% |
| 未授权项目访问事件 | 0 |
| 协作功能导致个人版流程变慢 | 0 个核心步骤增加 |

## 12. 风险与退出条件

- 如果多数用户仍通过即时通讯完成审核，说明站内协作价值不足，应停止扩建。
- 如果团队功能使个人版导航、启动时间或维护成本显著上升，应拆成独立部署或付费模块。
- 如果无法做到可靠项目隔离，不上线外部访问。
- 如果团队席位收入不能覆盖认证、通知、存储和支持成本，不进入企业化阶段。

## 13. 与当前个人版的关系

当前个人版继续优化以下基础能力：

- 首次成片成功率和镜头通过率。
- 角色、道具和场景一致性。
- 关键帧与视频候选择优。
- 单镜返工、版本对比和内部批注。
- 成本、耗时、失败恢复和最终交付。

这些指标未达标前，多人协作只保留本文档，不恢复运行代码或产品入口。
