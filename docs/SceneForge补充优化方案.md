# SceneForge 补充优化方案

> 更新日期：2026-07-31
> 适用范围：SceneForge / SceneForge 当前桌面端、Web 端及生成流水线
> 说明：本文补充模型接入、IP 连续性、质量成本闭环之外的产品与工程优化项。

## 1. 优化目标

SceneForge 当前面向个人创作者。下一阶段首先提高生成效果和日常可用性：降低首次使用门槛、减少无效调用、提升关键帧与镜头首次通过率，并让等待、费用和失败原因可预期。团队协作和商业化能力不占近期主线。

建议重点衡量以下结果：

- 用户能否在较少配置的情况下完成第一次成片。
- 多镜头任务能否在失败或重启后可靠恢复。
- 未变化的产物能否被复用，避免重复生成和重复计费。
- 质量问题能否被准确定位到具体镜头、具体版本和具体原因。
- 角色、场景和风格资产能否在后续项目中持续复用。
- 均衡档和高质量档能否用可接受的额外成本，显著降低坏关键帧进入视频模型的概率。

> 当前进展（2026-07-31）：质量档位已改为真实生成策略。省钱档为单关键帧/单视频候选；均衡档每个关键帧生成 2 张并由视觉模型选优；高质量档每个关键帧生成 3 张选优、每镜生成 2 个视频候选。候选选择失败时自动保留首个成功结果，不阻塞成片。

## 2. 降低首次成功门槛

当前用户需要理解 LLM、图像模型、视频模型、TTS、API 地址和模型名称，认知负担较高。应优先降低从安装到第一条成片之间的配置成本。

### 2.1 启动自检

- 一次检查 API Key、模型连通性、账户余额、FFmpeg、磁盘空间和写入权限。
- 分别测试文本、图像、视频和语音服务，明确具体失败环节。
- 对模型名不存在、接口协议不兼容、余额不足和网络超时给出不同提示。
- 在正式创作前展示当前配置支持的画幅、时长、参考素材和音频能力。

### 2.2 默认配置与试跑

- 为普通用户提供经过验证的推荐配置，隐藏不必要的高级参数。
- 增加低成本试跑模式，默认使用 1 个场景、2 个镜头和较低质量档位。
- 内置可直接审核、重生成和导出的完整示例项目。
- 第一阶段只提供少量场景预设，例如短剧、商品广告和知识视频。
- 用户选择用途后自动设置画幅、镜头数量、字幕、配音和质量档位。

## 3. 结构化提示词生产体系

多个 Agent、资产约束和 Skill 同时追加文本时，容易出现提示词膨胀、约束冲突和来源不明。建议将提示词生成升级为结构化的镜头执行计划。

### 3.1 镜头执行计划

每个镜头至少包含以下结构：

```text
叙事目标
角色与资产约束
场景连续性
构图与镜头
人物动作
台词与声音
禁止项
模型专用参数
```

### 3.2 Provider 专用编译

- 内部执行计划保持供应商无关。
- 为 Seedance、Veo 等模型分别生成适配其能力的最终提示词和参数。
- 保存每条约束的来源，包括用户输入、角色资产、连续性规则、风格 Skill 和系统默认值。
- 提交前检测互相矛盾的动作、人物数量、时长和参考素材要求。
- 保存执行计划、编译结果和模型响应版本，便于定位质量回退。
- 修改单一维度时保留其他锁定约束，例如只改动作而不改变人物服装。

## 4. 任务执行与性能优化

多镜头生成应基于依赖关系调度，而不是简单提高全局并发。

### 4.1 依赖图调度

- 无依赖镜头并行生成。
- 依赖上一镜尾帧、场景锚点或角色状态的镜头按依赖顺序执行。
- 用户修改上游产物时，只将受影响的下游节点标记为过期。
- 提交重生成前展示受影响镜头范围和预计增量成本。

### 4.2 缓存与增量生成

- 使用输入 Hash 识别并复用未变化的剧本、分镜、关键帧、TTS 和视频片段。
- 持久保存远程任务 ID、下载地址和轮询状态，服务重启后继续等待原任务。
- 下载完成的远程产物进入本地缓存，避免重复下载。
- 角色参考图、场景参考图和通用音效采用内容寻址存储，减少重复文件。
- 对不同 Provider 分别设置并发、限流和重试策略。
- 支持项目优先级和暂停，让高优先级任务获得生成配额。

## 5. 分层质量检查

质量检查应拆成低成本的确定性技术检查和高成本的视觉语义检查，避免所有问题都调用多模态模型。

### 5.1 技术检查

- 文件是否存在、可解码且不是黑屏或静帧异常。
- 分辨率、画幅、帧率、编码格式和时长是否符合要求。
- 音轨是否存在，是否出现削波、静音或明显响度异常。
- 拼接后是否丢帧、音画时长不一致或转场失败。
- 字幕、钩子和 AIGC 标识是否超出安全区域。
- 首帧、尾帧和封面文件是否有效。

### 5.2 视觉语义检查

- 人物身份、服装、场景和关键道具是否连续。
- 动作是否符合分镜，人物数量是否正确。
- 构图、审美和镜头运动是否达到项目要求。
- 首尾帧及视频采样帧是否发生明显畸变或跳变。
- 自动检查只给出证据、评分和建议，默认由用户确认是否重生成。
- 只有在有明确成本上限和稳定历史数据后，才启用自动重生成。

## 6. 安全与数据治理

从本地工具走向可交付产品前，需要补齐密钥、用户数据和生成素材的安全边界。

### 6.1 密钥与日志

- API Key 从明文 YAML 迁移到 Windows Credential Manager 或其他加密密钥库。
- 配置文件只保存密钥引用和非敏感参数。
- 日志自动脱敏 API Key、访问令牌、手机号和其他个人信息。
- 诊断包默认不包含原始密钥和完整敏感提示词。

### 6.2 数据隔离与来源

- 项目、任务、媒体文件和资产按用户或工作空间隔离。
- 多个访问 Token 只解决访问授权，不应被视为完整的多租户隔离。
- 角色照片和声音克隆记录授权人、授权范围和授权时间。
- 上传素材记录来源、许可证、允许用途和到期时间。
- 保存生成模型、版本、时间、参数和输入素材的审计信息。
- 支持项目导出、备份、迁移、保留策略和彻底删除。

## 7. 可观测性与故障诊断

系统需要把“生成失败”拆成用户可以理解和处理的具体原因。

### 7.1 错误分类

- Provider 排队或限流。
- 余额不足或鉴权失败。
- 内容审核拒绝。
- 模型不支持当前参数或参考素材。
- 网络超时、远程任务失败或下载失败。
- 本地转码、字幕、音频或拼接失败。
- 用户取消、任务超时或服务重启中断。

### 7.2 运行指标

- 统计各 Provider 和模型的成功率、重试率及失败原因分布。
- 记录生成耗时的 P50、P95 和排队时间。
- 记录每个镜头从提交到最终通过的完整调用链。
- 提供脱敏诊断包，包含任务状态、模型配置摘要、失败阶段和必要日志。
- 为远程接口建立健康状态，异常时阻止继续批量提交并提示用户。

## 8. 协作能力

当前产品面向个人创作者，多人协作不在运行版本中。外部审核链接、访客审核页、多管理令牌和协作意见收件箱已移除。个人版继续保留绑定镜头版本和时间点的内部批注、批量接受、版本恢复和局部返工。

未来多人协作的重新立项条件、权限模型、阶段范围和安全边界统一见 `docs/多人协作产品规划.md`。

## 9. 商业与增长指标

增长评估不应只看注册数或生成次数，应关注用户是否成功完成作品并复用资产。

建议追踪：

- 首次成功生成分镜的比例。
- 首次成功导出成片的比例。
- 用户七天内创建第二个项目的比例。
- 角色、场景或风格资产被跨项目复用的比例。
- 每个最终通过镜头的平均生成次数和成本。
- 单镜返工相对整片重做节省的时间和费用。
- 用户在剧本、分镜、镜头和成片审核阶段的流失率。
- 各类项目模板的首次通过率和复用率。

建议将以下指标作为中期留存指标：

> 用户是否在第二个项目中复用了第一个项目的角色、场景或风格资产。

发生跨项目复用后，SceneForge 才真正形成数据沉淀和迁移成本。

## 10. 实施优先级

### P0：影响首次成功与安全交付

- 启动自检与模型连通性测试。
- 细分错误类型并提供可执行的恢复建议。
- 记录真实调用成本和任务耗时。
- API Key 加密存储与日志脱敏。
- 建立确定性技术质检。
- 提供低成本试跑和完整示例项目。

### P1：提升效率与可解释性

- 结构化镜头执行计划和 Provider 专用提示词编译。
- 镜头依赖图、输入 Hash 和增量生成。
- Provider 独立并发、限流和恢复策略。
- 视觉质检证据化及人工确认机制。
- 批量审核、批量重生成和诊断包。
- 建立模型成功率、成本和用户接受率统计。

### P2：扩大交付和商业能力

- 多用户数据隔离、项目角色和镜头级协作。
- 素材许可证、肖像和声音授权管理。
- 项目备份、迁移和保留策略。
- 分享审核链接和外部客户审核。
- 在留存得到验证后建设 Skill 市场和更完整的商业体系。

## 11. 暂不建议优先投入

- 开发完整的专业时间线剪辑器。
- 接入大量只有基础文生视频能力、缺少完整恢复和参数映射的模型。
- 在用户留存未经验证前建设公开 Skill 市场。
- 默认开启无成本上限的自动质检和自动重生成。
- 继续增加缺少明确用户任务的 Agent 角色。
- 同时覆盖短剧、广告、口播、MV、小说和互动视频等所有场景。

现阶段应优先提高首次成片成功率、关键帧与镜头首次通过率、跨项目资产复用率和单镜返工效率。只有这些指标形成稳定优势后，新增模型、市场和协作功能才会持续放大产品价值。
