# SceneForge 与直接使用视频模型的竞争分析及强化路线

> 分析日期：2026-07-30
> 分析对象：当前 `SceneForge` Web 与生产流水线
> 对比范围：直接使用 Seedance、Veo 等视频生成模型或其官方创作产品

## 实施状态（2026-07-31）

- P0 多视频模型 Profile、能力声明、路由与真实执行链路已完成。
- P1 IP 生产记忆第一批已完成：角色/场景/道具圣经、逐镜连续性账本、最小充分参考集，以及重生成影响预览。
- P1 IP 生产记忆第二批已完成：跨集/跨场状态继承、上一集末帧参考、资产版本指纹、精准失效传播，以及连续性异常修复建议。
- P1 质量与成本数据闭环第一批已完成：镜头级生成事实、人工通过/返工/版本选择事件、项目指标看板、供应商账单覆盖率，以及达到样本门槛后的历史表现路由。
- P1 返工与审核体验第一批已完成：当前版/历史版并排对比、批量选择与依赖去重、人物/构图/动作/声音锁定约束，以及返工前影响范围和新增费用预览。
- P1 返工与审核体验第二批已完成：批注绑定具体镜头版本和时间点、批量接受当前版本、批量恢复上一可用版本，以及局部返工相对整片重做的镜头/时间/费用节省预览与累计指标。
- P2 轻量交付第一批已完成：终审时间线支持镜头排序、逐镜入出点裁剪、项目级硬切/交叉溶解/淡入淡出、后台重新合成，以及非破坏式恢复原始成片。
- P2 轻量交付第二批已完成：对白触发 BGM 自动压低，支持三档压低强度；终审页提供项目级字幕时间线，可校正文本和时间、归档恢复并下载 SRT。
- 个人版质量策略第一批已完成：省钱档保持单候选；均衡档为每个关键帧生成 2 张并自动选优；高质量档为每个关键帧生成 3 张选优，并为每镜保留 2 个视频候选。费用预估按真实候选请求数计算。
- 当前产品明确面向个人创作者。外部审核链接、访客审核、多管理令牌和协作意见收件箱已从运行代码移除；未来方向见 `docs/多人协作产品规划.md`。
- 下一阶段聚焦个人创作的首次成片成功率、关键帧通过率、单镜返工次数、等待时间可预期性，以及质量策略的真实效果基准。

## 1. 核心结论

SceneForge 不应被定位成“比 Seedance 更强的视频模型”，而应被定位成视频模型之上的生产控制层。

一句话概括：

> Seedance 擅长生成一个镜头，SceneForge 应当擅长持续完成一部作品。

对于单个短片段、模型能力尝鲜和高自由度即时创作，用户直接使用 Seedance、Veo 等官方产品通常更快，也更容易获得最新模型能力。SceneForge 的成立条件，是用户需要多镜头叙事、固定角色和资产复用、分阶段审核、局部返工、失败恢复、成本控制及最终交付。

因此，SceneForge 的竞争对象不是某个视频模型本身，而是用户在模型页面、素材目录、提示词文档和剪辑软件之间手工维持的整套流程。

## 2. 当前平台已经具备的生产能力

以下能力已能在当前代码中找到对应实现，不只是路线图设想。

### 2.1 分阶段生产和审核

当前工作流按以下阶段推进：

```text
主题或剧本
  -> 剧本审核
  -> 分镜脚本审核
  -> 关键帧/镜头视频审核
  -> 成片终审
  -> 发布
```

系统支持：

- 主题生成和剧本导入两种入口。
- 剧本、分镜、镜头视频和成片四个审核闸门。
- 分镜阶段生成低成本关键帧预览。
- 按自然语言要求修改当前阶段。
- 手动编辑、增加或删除分镜。
- 服务中断后继续生成。

主要代码入口：

- `services/workflow_engine.py`
- `frontend/src/components/CreateForm.vue`
- `frontend/src/components/ReviewContent.vue`

### 2.2 可复用的IP资产

平台已经支持角色、道具和场景三类资产，并能将固定角色参考图注入镜头生成流程。角色画像还具备历史版本能力。

这使平台可以逐步从“一条视频中的一致性”扩展到“跨视频、跨集的IP复用”。

主要代码入口：

- `characters/`
- `frontend/src/views/AssetModels.vue`
- `frontend/src/views/Characters.vue`

### 2.3 单镜返工、版本和回滚

平台可只重生成指定镜头，并计算受该镜头影响的依赖镜头。旧版镜头文件不会直接覆盖，而是进入归档或版本系统，用户可以查看历史结果并回滚。

主要代码入口：

- `pipelines/script2video_pipeline.py`
- `services/artifact_versions.py`
- `frontend/src/components/ReviewContent.vue`

### 2.4 后期和交付

当前后期链覆盖：

- 独立TTS配音。
- 配音时间轴和字幕时间轴对齐。
- BGM、音效和响度规范化。
- 字幕烧录。
- 镜头转场。
- 开场钩子。
- 封面导出。
- AIGC显式标识和视频元数据。

主要代码入口：

- `audio/`
- `subtitles/`
- `video/`
- `utils/video.py`

### 2.5 成本、任务和恢复

平台在昂贵的视频生成前提供镜头数、场景数和预计成本检查，并使用持久任务队列处理长时间生成任务。服务重启后能够识别被中断的任务，也具备远程模型任务恢复逻辑。

主要代码入口：

- `services/budget.py`
- `services/cost.py`
- `services/durable_job_runner.py`
- `services/local_worker.py`

## 3. 与直接使用 Seedance 或其他模型的对比

| 对比维度 | 直接使用模型或官方产品 | 当前 SceneForge |
| --- | --- | --- |
| 单镜头画质、动作和口型 | 通常更强，直接获得原生能力 | 上限仍由底层模型决定 |
| 最新模型能力 | 厂商平台最先上线 | 需要等待接口和参数适配 |
| 首次上手 | 输入提示词即可生成 | 需要配置多个模型和密钥 |
| 单次生成成本 | 调用链短，通常更低 | 可能调用LLM、图像、视频、TTS和质检模型 |
| 多镜头故事 | 需要用户自行规划和管理 | 自动拆解剧本、场景、机位和镜头 |
| 固定角色/IP复用 | 模型参考能力强，但项目沉淀取决于厂商 | 可建立本地角色、服装、道具和场景资产 |
| 修改返工 | 常需重新生成并手工管理版本 | 支持单镜重生成、依赖联动、版本和回滚 |
| 审核协作 | 取决于厂商产品 | 已有明确的阶段审核和修改流程 |
| 后期交付 | 常需再进入剪辑软件 | 可自动完成配音、字幕、BGM、转场和封面 |
| 长任务可靠性 | 依赖厂商项目页 | 本地持久任务、重试、续跑和远程任务恢复 |
| 模型自由度 | 被单一厂商生态约束 | 架构上可支持多个模型和供应商 |
| 数据和资产控制 | 项目主要保存在厂商云端 | 项目元数据和资产主要保存在本地工作区 |

## 4. SceneForge 的真实优势

### 4.1 从生成能力变成生产能力

视频模型解决的是“根据输入生成一个结果”，SceneForge 解决的是“如何把多个不稳定的生成结果组织成可审核、可修改和可交付的项目”。

其价值不在于单次生成质量必然更高，而在于：

- 昂贵生成前可以先审核剧本、分镜和关键帧。
- 某个镜头失败时不必重新生成整片。
- 用户修改有明确的影响范围。
- 每个阶段有可追踪状态和历史版本。
- 中断和供应商波动不会轻易丢失整个项目。

### 4.2 跨项目的IP资产沉淀

官方模型的参考图能力可以解决单次生成中的人物一致性，但内容团队真正需要的是长期复用：同一个人物、服装、声音、道具和场景持续出现在多集内容中。

如果 SceneForge 能稳定管理这种跨项目记忆，它就不再只是模型调用界面，而会成为用户的内容资产库。

### 4.3 降低返工浪费，而不是降低API单价

SceneForge 不应宣传“每次生成更便宜”。完整流水线可能使用更多模型调用，单次成本反而可能更高。

合理的经济价值是：

- 在视频生成前发现剧本和分镜问题。
- 通过关键帧发现人物、构图和场景问题。
- 只重生成失败镜头。
- 通过版本对比避免错误覆盖可用结果。

最终应比较的是“每个通过审核镜头的成本”和“完成一条成片的总成本”，而不是某个模型的标价。

### 4.4 降低模型迁移成本

不同模型支持的画幅、时长、参考数量、首尾帧和音频能力不同。SceneForge 已经有模型能力注册和提交前检查的基础。

如果这一层发展成熟，用户可以保留自己的角色资产、分镜、版本和生产记录，只替换渲染模型，而不必迁移整个生产体系。

## 5. 当前平台的现实短板

### 5.1 直接模型也在快速平台化

Seedance 2.0 已支持文本、图片、音频和视频参考，并强化了表演、光影和运镜控制。模型厂商也在增加故事规划、角色一致性、编辑和项目管理能力。

因此，“多模态参考”“多镜头”“一站式生成”已经不足以构成 SceneForge 的独特卖点。

### 5.2 最新模型适配存在滞后

当前配置后台主要预置 Seedance 1.5/1.0 和 Veo 3.1，尚未把 Seedance 2.0 的完整多模态输入映射到平台工作流。

如果用户在官方产品中可以直接使用新模型，SceneForge 在单镜质量、音画同步和控制能力上可能暂时落后。

### 5.3 多模型路由尚未完全落地

代码已经有 `ProviderRegistry` 和模型能力对象，但 Web 服务启动时主要从当前配置的一套图像模型和一套视频模型创建能力表。

这更接近“当前模型是否支持本项目”的提交前检查，还不是真正的多模型自动选择、失败切换和成本质量路由。

### 5.4 质量检查还不能构成稳定承诺

人物一致性和多维质量检查默认关闭，因为自动检查和重生成会增加成本与等待时间。即使开启，视觉模型评分也不能完全替代人工审核。

平台目前可以提供辅助判断，但还不应承诺稳定的“自动专业品质”。

### 5.5 独立配音与原生音画生成各有取舍

独立TTS有利于跨镜头、跨集保持同一声线，也便于替换台词和控制字幕时间轴。但后期叠加配音不天然具备准确口型同步。

Seedance 原生音画联合生成在对话表演、环境声和口型同步上可能更有优势。平台需要允许用户按镜头选择原生音频、独立配音或混合方案。

### 5.6 当前不以多人生产SaaS为目标

当前产品首先服务个人创作者，不提供外部审核链接、多人账号、项目成员权限、团队配额或组织审计。

平台也不应在近期尝试完整复刻 Premiere 或剪映的专业时间线编辑器。

## 6. 目标用户

### 6.1 最适合的用户

- 连续生产短剧、IP故事、知识视频或个人商业内容的独立创作者。
- 一条作品包含多个镜头，无法接受每次修改都整片重做的用户。
- 需要固定人物、服装、道具和场景跨视频复用的个人创作者。
- 希望保留本地资产，并能更换模型供应商的专业用户。
- 不想手工完成拆分镜、文件命名、下载、拼接、配音和字幕的创作者。

### 6.2 不适合优先争取的用户

- 只想生成一个短片段的轻度用户。
- 主要目标是第一时间体验最新模型的用户。
- 已经拥有成熟制片、资产管理和剪辑流水线的大型团队。
- 只关心单次生成最低价格，而不关心返工和项目管理的用户。
- 需要复杂特效、逐帧调色和专业声音设计的重度后期用户。

## 7. 建议的产品定位

不建议使用以下定位：

- Seedance 平替。
- 比 Seedance 画质更高。
- 一句话自动生成电影。
- 自动选择全网最优模型。

建议使用：

> 把 Seedance、Veo 等生成模型，变成可审核、可续跑、可局部返工、可沉淀角色资产的AI短片生产系统。

面向系列内容时，可以进一步收窄为：

> 一次建立角色与风格，持续交付可审核、可返工的多镜头成片。

## 8. 下一步强化方向

### P0：补齐模型层

目标是避免平台在最新模型能力和简单任务体验上明显落后。

1. 接入 Seedance 2.0 的图片、视频和音频多模态参考。
2. 将单一模型配置升级为多个 Provider Profile，可同时启用 Seedance、Veo 等。
3. 为每个模型准确登记画幅、分辨率、时长、参考素材、音频、价格和恢复能力。
4. 在分镜审核阶段展示推荐模型、预计成本和推荐原因，并允许人工覆盖。
5. 提供单镜直出模式，简单需求不强制经过完整流水线。
6. 提供明确的能力降级提示，禁止静默丢弃模型不支持的输入。

### P1：把资产库升级成IP生产记忆

目标是形成厂商模型页面难以替代的跨项目能力。

1. 建立角色圣经：脸、发型、体型、服装版本、年龄、声线、性格和禁改项。
2. 建立场景圣经：空间布局、固定物件、光照、时间、天气和色彩基调。
3. 建立道具状态：归属、外观、损坏程度、出现位置和镜头间变化。
4. 建立连续性账本：人物站位、手持物、服装、情绪、伤痕和时间推进。
5. 自动为每个镜头选择最小充分参考集，减少参考冲突和无效输入。
6. 支持跨集继承资产和连续性状态。
7. 修改资产时只将真正受影响的镜头标记为过期。

### P1：建立质量与成本数据闭环

目标是用真实生产数据证明平台价值，而不是依赖功能数量。

每次生成应记录：

- 模型、供应商和版本。
- 提示词、负面约束和参考素材。
- 请求参数、远程任务ID和重试记录。
- 排队时间、生成时间和下载时间。
- 供应商实际费用或可核对的计费数据。
- 自动质检分数和失败维度。
- 用户接受、拒绝、重生成及原因。
- 最终采用的产物版本。

早期质量检查应以建议为主：系统指出问题，用户确认后再重生成，避免后台静默增加费用。积累足够数据后，再按镜头类型逐步启用自动决策。

#### 已落地（2026-07-31）

- 每个镜头在场景目录保存不可变生成历史，记录路由 Profile、供应商、模型、完整执行提示词、负面约束、参考素材、请求参数、远端任务 ID、逐次重试、排队/生成/下载耗时和候选选择。
- 成本明确区分三种状态：供应商回传的实际费用、Profile 静态单价推导的估算区间、无可用计费数据；估算不会标成实付。
- 分镜视频审核“通过”、单镜重生成和历史版本选择写入项目内决策事件；重生成记录人物、动作、连续性、构图、技术质量等原因维度。
- `GET /api/production/{sid}/metrics` 汇总首次通过率、质量通过率、返工次数、请求/重试数、平均排队与生成时间、单镜成本和模型表现。
- 镜头审核页展示项目指标和单镜生产事实；模型历史通过率、耗时与每个通过镜头的估算成本达到 5 个已决策样本后才参与路由，样本不足时保留原有能力/质量档/静态价格排序。
- 当前实际费用覆盖率取决于供应商是否在进度事件中明确返回 `actual_cost`；未返回时只展示估算。图像、TTS、质检等非视频调用的统一账单仍属于后续扩展。

### P1：强化返工和审核体验

第一批已完成：

1. 视频历史区支持当前版与任一历史版并排播放和选择回滚。
2. 审核看板支持批量勾选不合格镜头；连续性账本合并重复依赖，只提交最小执行根。
3. 单镜和批量返工均可设置人物、构图、动作、声音锁定。锁定会进入首帧和视频模型提示约束及决策日志，但不承诺像素级完全不变。
4. 提交前展示选中镜头数、实际受影响镜头数、执行根数和预计新增费用。费用下限按受影响镜头与候选数计算，上限包含配置的重试次数；未配置 Profile 单价时明确显示无法估价。
5. 批量返工作为一个 `workflow.regenerate_shots` 持久任务串行执行，保留单会话单飞、取消边界、版本归档和最终成片重建。

第二批已完成：

1. 审核意见已绑定到具体镜头、具体视频版本和可选时间点，历史版本切换后批注仍归属于原版本。
2. 批量审核支持“一键接受本批次”和“恢复上一可用版本”；恢复会跳过无可用旧版的镜头，并在完成后只统一重建一次成片。
3. 返工预览会比较局部返工与整片全部镜头重做，展示少生成镜头数、工作量节省比例、预计少等时间和预计少花费用。
4. 成功完成的批量返工会写入不可变决策事件，项目生产指标累计已完成批次数、少生成镜头数及有估价覆盖时的预计节省时间和费用。

### P2：补齐轻量交付，不重做专业剪辑软件

第一批已完成：

- 终审页从静态镜头条升级为项目级剪辑方案，支持用上移/下移调整镜头顺序。
- 每个镜头可设置入点和出点，后端校验镜头集合、裁剪边界、最短保留时长及转场时长。
- 支持硬切、交叉溶解和淡入淡出；界面实时计算预计输出时长，实际合成在持久后台任务中执行。
- 第一次应用剪辑时保存不可变原始成片源；每次重新合成或恢复前归档当前成片和方案，避免累计裁剪与不可逆覆盖。
- 镜头重新生成导致成片源变化时，旧剪辑方案标记为过期并载入新的默认方案。

第二批已完成：

- BGM 混音支持用对白作为侧链信号自动压低音乐，可在设置页选择轻柔、标准或明显三档；未启用配音时自动保持普通 BGM 混音。
- 混音输出显式受成片时长约束，循环 BGM 与补静音侧链不会产生无限输出，真实 FFmpeg 链路已验证。
- 终审页增加项目级字幕时间线，统一聚合逐场配音时间轴或 SRT，并跟随已应用的镜头排序、裁剪和交叉溶解重新映射。
- 字幕文本和起止时间可编辑，保存时校验行集合、顺序、边界和最短显示时间；旧文件自动归档，可恢复生成字幕或下载标准 SRT。
- 打开字幕面板只读取数据，不写入项目目录；只有保存、恢复或下载时才生成项目级字幕文件。

后续建议增加：

- 台词时间轴和配音替换。
- 字幕安全区、品牌模板和封面模板。
- 横屏成片自动生成竖屏和方形衍生版本。
- 导出到剪映、Premiere或通用 EDL/XML 工程。

复杂特效、精细调色和逐帧声音设计继续交给专业工具。

### P2：团队能力暂缓

多人协作不在当前运行版本中。项目成员权限、评论负责人、站内通知、团队配额、外部审核链接和组织级资产库均不进入近期排期。只有个人版的首次成片成功率和复用留存达到明确门槛后，才按 `docs/多人协作产品规划.md` 重新立项。

## 9. 产品核心指标

不应以“生成次数”作为唯一增长指标。建议重点跟踪：

| 指标 | 说明 |
| --- | --- |
| 首次镜头通过率 | 第一次生成即被用户接受的镜头比例 |
| 每个通过镜头的成本 | 包含失败、重试、图像、视频和质检调用 |
| 单镜平均返工次数 | 反映提示词、参考素材和模型选择质量 |
| 局部返工节省比例 | 与整片重新生成相比节省的费用和时间 |
| 从创意到成片的时间 | 衡量完整生产效率 |
| 中断任务恢复成功率 | 衡量长任务可靠性 |
| 跨集角色通过率 | 衡量IP资产和连续性能力 |
| 成本预估误差 | 预估与实际供应商费用的偏差 |

这些指标还能为后续模型路由提供依据：不同模型不再只按宣传参数选择，而是按平台积累的真实镜头通过率、耗时和成本选择。

## 10. 建议的90天实施顺序

### 第1至3周：模型能力对齐

- 完成 Seedance 2.0 多模态输入适配。
- 引入多个 Provider Profile。
- 完善模型能力检查、明确降级和单镜直出。
- 建立固定测试集，对比官方直出与平台流水线结果。

### 第4至7周：IP连续性

- 完成角色、场景和道具圣经。
- 增加镜头连续性账本。
- 自动构建最小参考素材包。
- 扩展依赖图和精确失效范围。

### 第8至10周：数据闭环

- 记录供应商、耗时、成本、质检和人工选择。
- 上线首次通过率和每个通过镜头成本看板。
- 让质量检查先提供人工可确认的返工建议。

### 第11至12周：体验和案例

- 版本并排对比、版本时间点批注、批量接受/恢复/返工、锁定约束和返工费用及节省预览已完成。
- 轻量剪辑第一批已完成：镜头排序、入出点裁剪、基础转场、后台合成与恢复原始成片。
- 轻量交付第二批已完成：对白触发 BGM 自动压低、三档强度配置、项目字幕时间线编辑/恢复/下载。
- 关键帧多候选择优已完成：均衡档每帧 2 选 1，高质量档每帧 3 选 1；高质量档视频 2 选 1。
- 下一步用固定测试集验证三档的首帧通过率、视频通过率、耗时和单个通过镜头成本，并据此调整默认档位和候选数。
- 打磨一个可量化的连续短剧案例。
- 用真实数据展示节省的返工次数、时间和费用。

## 11. 推荐的演示和销售表达

最有说服力的演示不应是“一句话出片”，因为模型厂商也可以完成类似演示。

建议演示以下完整任务：

1. 建立固定角色、服装、声线、道具和场景。
2. 连续制作三集使用相同IP的短剧。
3. 创作者决定修改第二集的一句台词和一个动作。
4. 系统明确展示受影响的两个镜头。
5. 只重生成相关镜头，并保留旧版本供对比。
6. 自动重新合成配音、字幕、BGM和竖屏成片。
7. 展示实际新增成本，以及相较整片重做节省的时间和费用。

这个案例直接证明 SceneForge 的核心价值：不是多调用一次模型，而是让不稳定的生成过程变得可管理。

## 12. 暂不建议投入的方向

- 同时覆盖短剧、小说、口播、广告、MV和互动视频的全部场景。
- 在缺少真实质量数据时开发复杂的“智能自动路由”。
- 自研完整非线性剪辑器。
- 继续增加大量名称不同但职责重叠的 Agent。
- 用更多自动重试掩盖提示词、参考素材或模型能力不匹配。
- 在项目工作流尚未稳定前建设复杂的企业多租户系统。

## 13. 最终判断

SceneForge 当前已经具备生产工作台的基础，不需要推倒重写。真正的问题不是功能数量不够，而是尚未把已有能力压缩成一个清晰、可量化、难以被模型厂商替代的核心价值。

推荐聚焦“固定角色的连续多镜头内容生产”，并围绕以下三项形成壁垒：

1. 跨项目IP和连续性记忆。
2. 可审核、可比较、可局部返工的版本工作流。
3. 基于真实通过率、成本和耗时的多模型生产决策。

当平台能稳定证明“同一批角色连续生产多集，修改局部时只重做必要镜头，并准确节省费用和时间”，用户才会因为生产效率而留下，而不是因为平台暂时接入了某个模型。
