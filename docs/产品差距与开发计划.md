# SceneForge 产品完善开发计划

> 基于对 `SceneForge` 现有代码的实地走查,梳理当前产品的不足，并给出分阶段、可落地的开发计划。
> 编写日期：2026-06-22。配套既有文档：`docs/SceneForge可行性与重构计划.md`（实现历史与逐函数改造记录）。

---

## 0. 一句话定性

当前系统已能"从主题到一段连续画面"端到端跑通（消息/网页双通道、固定角色、中文字幕、分阶段人审、成本护栏均已落地）。
**但它产出的是"连续画面"，不是"作品"。** 从"能生成视频"到"能直接发布"之间，缺口几乎全在 **音频链** 与 **节奏/包装**，其次才是工程化与运维。

本计划据此把工作排成 P0（决定可用性）→ P1（决定观感）→ P2（决定可运营），按回报排序，而非按技术分层排序。

---

## 1. 现状（已完成，作为基线）

- 端到端流水线：topic → 剧本 → 分镜 → 视频 → 成片，每阶段 `ReviewTask` 人审闸门（`services/workflow_engine.py`）。
- 固定角色一致性：`characters/`（资产库 + 生产端短路注入），根治人物漂移。
- 中文 + 字幕烧录：`subtitles/`（解析 `[Speaker] 名 (情绪): 台词` → 时间轴 → .ass/.srt → ffmpeg burn-in，已解决 Windows 盘符冒号问题）。
- 双通道：控制台 + 飞书（真实 OpenAPI、验签、event_id 去重、3 秒 ACK + 后台执行）。
- 网页产品：Vue 工作台（`frontend/`）+ 统一服务 `main_server.py`。
- 后台任务化：`services/job_runner.py` + `services/production_service.py`（守护线程、单飞、并发上限、完成推送）。
- 鉴权与护栏：单令牌鉴权（`server/app.py`）、成本闸 `services/budget.py`（视频阶段前卡场景/镜头上限）。
- 测试：约 284 项通过（两项 Windows 环境基线失败，与改动无关）。

## 2. 不足清单（实地走查，按严重程度）

### A. 内容质量链 —— 最致命，直接决定成片能否使用

| # | 问题 | 位置 / 证据 | 影响 |
|---|---|---|---|
| A1 | **无独立配音/旁白(TTS)**：`audio_desc` 被直接拼进视频提示词，声音交给 Seedance 逐片段即兴生成，无统一旁白、无台词对齐 | `pipelines/script2video_pipeline.py:659` | 成片"哑"或音画不连贯；中文短剧/推文 80% 靠配音 |
| A2 | **无 BGM、无音效混合** | 全仓无背景音乐/音效混音逻辑 | 没有情绪铺垫，完播率崩 |
| A3 | **镜头硬切，无转场** | `utils/video.py:37` `concatenate_videoclips` 默认 chain | 跳切感强，廉价 |
| A4 | **拼接可能丢音轨、无响度规范化** | `utils/video.py:26-44` | 各片段音量不一、音轨处理脆弱 |
| A5 | **字幕样式单一、无封面/钩子帧** | `subtitles/renderer`、无封面逻辑 | 缺前 3 秒钩子（短视频生死线） |

> 关键复用点：`subtitles/extractor.py:extract_spoken_content` 已能解析对白行与 `[Sound Effect]` 标记，
> 可直接作为 **TTS 配音文本** 与 **音效触发** 的数据源，A1/A2 不需要新建解析层。

### B. 可靠性 / 健壮性

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| B1 | 分片级**自动重试/退避**缺失（模型 API 抖动如 503 需人工重发） | 渲染各 `generate_*` 调用 | 长任务易中断 |
| B2 | **磁盘无清理**：frames/shots/`_archive/v{n}` 长期堆积 | 各 `working_dir` | 占满磁盘 |
| B3 | **资产无版本管理**：角色画像"优化"覆盖、无回滚 | `characters/asset_registry.py` | 改坏无法退回 |

### C. 产品化 / 多用户

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| C1 | **单一共享 token，无账号体系** | `main_server.py:58` | 多人用裸奔、无法区分操作者 |
| C2 | **无用量/成本看板**：能卡上限但看不到"这条片花了多少钱" | `services/budget.py` | 成本不可见 |
| C3 | **config/registry 写入无锁** | `server/config_service.py`、`asset_registry.py` | 并发写损坏文件 |

### D. 可观测性 / 部署

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| D1 | **无结构化日志、无任务历史持久展示**（靠 print） | 全局 | 排障困难 |
| D2 | **stdlib `http.server` 不适合生产** | `server/app.py` `serve()` | 无优雅重启、并发弱 |

### E. 前端 / UX

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| E1 | **轮询而非实时进度(SSE)** | Vue 前端 + `production_api` | 长任务盯转圈 |
| E2 | 早期单文件原生 HTML 的交互与响应式问题（已迁移至 Vue） | `frontend/` | 体验粗糙 |

### F. 合规

| # | 问题 | 影响 |
|---|---|---|
| F1 | **无 AIGC 标识 / 内容审核** | 国内硬要求，B 端不可用、平台限流 |

## 3. 开发计划（分阶段，按回报排序）

> 工作量为粗估（理想人日，单人）。每项给出：目标 / 主要改动 / 涉及文件 / 验收标准。
> 沿用既有原则：**新增为主、默认关闭**，不污染 ViMax 上游路径，便于未来合并升级。

### 阶段 P0 —— 让成片"能发"（音频链）

把"哑片"变成"能直接发布的片"。这是回报最大的阶段，先做。

#### P0-1　配音 / 旁白（TTS）　【✅ 已完成 2026-06-22】
- **目标**：每个镜头按台词/旁白生成配音轨，与镜头时长对齐，混入成片。
- **落地**：新增 `audio/` 包（`tts_provider.py` OpenAI 兼容 `/audio/speech` 提供方、`mixer.py` ffmpeg `adelay`+`amix` 按字幕时间轴摆放并 `-c:v copy` 免重编码、`service.py` `VoiceoverService` 门面）。复用 `subtitles` 的 `build_track` 取台词与时间轴。`script2video_pipeline.__call__` 在 concat 后、字幕烧录前插入 `_maybe_add_voiceover`；CLI 经 `init_from_config`、agent/web 经 `sceneforge_adapters._build_voiceover_service` 注入；配置 `audio.tts`（默认 disabled）。新增 `tests/test_audio.py`（13 例），全量 297 passed。
- **默认关闭**：未开 `audio.tts.enabled` 时行为与原版逐字节一致。
- **遗留**：① 需确认 yunwu 网关实际可用的 TTS 模型名（默认填 `tts-1`，与早期 image/video 模型名一样可能要改）；② 当前对齐用字幕时间轴估算，TTS 实际时长驱动留到 P0-3。
- **改动**：
  - 新增 `audio/tts_service.py`（`TTSService`，可配 provider；输入 `SubtitleLine` 列表 → 输出每行 wav + 时长）。
  - 复用 `subtitles/extractor.py:extract_spoken_content` 取台词（无需新解析）。
  - 在 `script2video_pipeline.py` 渲染末段（concat 后、`_maybe_burn_subtitles` 前）合成镜头配音轨。
  - 配置：`configs/*.yaml` 新增 `audio.tts`（默认 disabled）。
- **验收**：开启后成片含与字幕同步的中文配音；关闭则行为与现状逐字节一致。

#### P0-2　BGM + 音效 + 音频混合/响度规范化　【✅ 已完成 2026-06-22】
- **目标**：成片铺底乐、按 `[Sound Effect]` 触发音效、统一响度。
- **落地**：`audio/mixer.py` 增 `build_audio_filter`/`build_audio_inputs`/`mux_audio`——**配音 + 音效 + BGM 一次 ffmpeg 合成**（`adelay` 摆位、`amix` 混音、`loudnorm` EBU R128 规范化、BGM 经 `-stream_loop -1` 循环铺满、`-c:v copy` 免重编码）。`audio/sfx.py`（`extract_sound_effects` 解析 `[Sound Effect]`、`resolve_sfx_file` 按关键词匹配素材库）。`service.py` `VoiceoverService` 升级为完整音频后期门面（`add_audio` 合成 voiceover/sfx/bgm/loudnorm；`resolve_bgm_path` 支持单文件或目录取首个）。BGM/SFX **无对话也生效**；缺素材则静默跳过。`script2video_pipeline._maybe_postprocess_audio` 单趟处理。config 增 `audio.bgm`/`audio.sfx`/`audio.loudnorm`（bgm/sfx 默认 disabled，loudnorm 默认 on）。adapter 路径同步支持。`tests/test_audio.py` 扩至 29 例，全量 313 passed。
- **遗留**：BGM 需用户提供音乐文件（版权自负）；SFX 需用户建素材库（按关键词命名文件，如 `thunder_clap.mp3`），否则跳过。

#### P0-3　字幕时间轴对齐配音　【✅ 已完成 2026-06-22】
- **目标**：字幕时间轴改为以 TTS 实际配音时长驱动，而非估算；配音与字幕共用同一条时间轴。
- **落地**：`VoiceClip` 加 `duration`；`mixer.probe_audio_duration` 探测 TTS 音频真实时长；`VoiceoverService.synthesize_track` 合成后测时长，`_shot_starts`（累计镜头起点）+ `retime_track`（每行按真实时长在所属镜头内顺序摆放、锚定镜头起点，同时回写每个 voiceover clip 的 start）；新增 `render_audio` 返回 `(成片, 重定时 track)`。`script2video_pipeline.__call__` 把重定时 track 透传给 `_maybe_burn_subtitles`（新增 `precomputed_track` 形参，复用同一时间轴），并将重定时 track 持久化 `audio/voiced_track.json`，断点续跑重载、避免重复计费 TTS。`tests/test_audio.py` 扩至 33 例，全量 317 passed。
- **已知取舍**：镜头内台词总时长超过镜头视频长度时配音会溢出到下一镜（不拉伸视频，留待 P1/后续）。

> **P0（音频链）已全部完成**。现在开启 `audio.tts/bgm/sfx` 后，产出的是**有配音、有 BGM、有音效、响度统一、字幕与配音逐句对齐**的可直接发布短片；全部默认关闭，关闭时与原版逐字节一致。

### 阶段 P1 —— 让成片"好看"（节奏 / 包装）

#### P1-1　转场　【✅ 已完成 2026-06-22】
- `utils/video.py` 加 `normalize_transition`/`_concat_with_transition`，`concatenate_video_files` 增 `transition` 形参；支持 `crossfade`/`dissolve`（moviepy `CrossFadeIn`+`method=compose`+负 padding 叠化）与 `fade`（`FadeIn/FadeOut` 过黑）。两条 pipeline（镜头间 + idea2video 场景间)透传，agent 路径同步，配置 `video.transition`（默认 `none` 硬切，与原版一致）。真机验证:同片硬切 20.25s vs crossfade(0.8s) 19.44s,恰好少 0.8s 叠化。tests/test_video_transition.py。

#### P1-3　字幕样式可配　【✅ 已完成 2026-06-22】
- 字体/字号/颜色/描边/位置原已接通；本次补 **`#RRGGBB` hex 颜色**（`_ass_color` 解析为 ASS `&HAABBGGRR`）+ **垂直边距 `margin_v`**（`SubtitleStyle.margin_v` → Style 行 MarginV，原硬编码 30）。config `subtitle.style` 已含全部字段。tests 扩展。

#### P1-2　封面 / 前 3 秒钩子帧　【机械层 ✅ 2026-06-22；内容层(LLM 钩子文案)待做】
- **方向定**(对标君東影视解说短视频)：海报封面图 ✅ + 前3秒文字钩子浮层 ✅ + LLM自动钩子文案(待做)；**不做片头标题卡**(解说类损完播)。
- **落地(机械层)**：新增 `video/cover.py:export_poster`(ffmpeg 抓帧出 .jpg 缩略图)。字幕渲染器 `render_ass` 加 `hook` 形参→注入第二个 `Hook` 样式 + layer-1 事件(0→N秒,大字居中靠上),**与字幕同一趟烧录,不额外重编码**。`SubtitleService.render_ass` 透传。pipeline 加 `hook`/`cover` 配置 + `__call__` 加 `hook_text` 形参(per-render 文案优先于 config),`_resolve_hook`/`_export_poster`,钩子无对话也能烧;idea2video 钩子仅作用于首场景、海报在最终拼接后导出;agent 路径透传(hook_text 取 session)。config 加 `video.hook`/`video.cover`(默认关闭)。真机验证:钩子浮层烧录 + 海报导出均成功。`tests/test_video_transition.py`(海报)+ `test_subtitles.py`(钩子)。全量 330 passed。
- **内容层(LLM 钩子文案)✅ 已完成 2026-06-22**：`agents/hook_writer.py:HookWriter`(用流水线 chat_model 一次调用，中/英 prompt，`_clean` 去标签/引号取首行)；script2video.__call__ 在钩子启用+`auto`+无手填时自动据剧本生成 `hook_text`；idea2video 据 story 生成、仅首场景加钩子；config `video.hook.auto`(默认 true)。真 LLM 实测产出"35岁被大厂开除 3个月后前总监求着我合作"。`tests/test_hook_writer.py`。

> **P1 全部完成**：P1-1 转场 ✅、P1-2 封面+钩子浮层+LLM文案 ✅、P1-3 字幕样式 ✅。

### 阶段 P2 —— 让产品"可运营"（工程性价比项）

按性价比挑，非全做。

#### P2-2　成本看板　【✅ 已完成 2026-06-22】

#### P2-3　磁盘清理策略　【✅ 已完成 2026-06-22】

#### P2-4　结构化日志 + 实时进度　【✅ 已完成 2026-06-22】

- 新增 `utils/atomic.py`：`atomic_write_text`(temp 文件 + `os.replace` 原子替换，Windows 上对 `PermissionError` 重试) + `file_lock`(进程内 per-path 可重入锁)。被新增的多写入方(BgmService/VoiceService 写两个 pipeline yaml、ConfigService 写 agent.local、CharacterAssetRegistry 写 registry)采用——读改写包在 `file_lock` 内、落盘走原子写，杜绝并发写撕裂/丢更新。`tests/test_atomic.py`(含并发压测)。

> **P2 全部完成**：P2-1 自动重试 ✅、P2-2 成本看板 ✅、P2-3 磁盘清理 ✅、P2-5 配置写锁 ✅（P2-4 结构化日志/任务历史未做，可选）。

### 阶段 P3 —— 上规模才需要（按需）

- **C1 多用户账号体系**：暂缓。早期多令牌鉴权已移除，当前版本只面向个人创作者并使用单一 `SCENEFORGE_WEB_TOKEN`。未来若满足立项条件，按 `docs/多人协作产品规划.md` 从账号、工作区和项目权限重新设计，不复用临时共享令牌方案。
- **D2 生产级部署**（uvicorn/gunicorn 后置）：~1 人日。仅当公网暴露时做。

- **E2 前端 React 化**：**建议不做** —— 现有单文件 UI 可用且易维护，整体重写高成本低回报。
- **内容审核**：✅ 接骨架完成(`services/moderation.py` keyword 模式可用并接入 start_topic 闸门；cloud 模式留接入点，需服务商凭证)。

## 4. 里程碑建议

| 里程碑 | 内容 | 工作量 | 产出 |
|---|---|---|---|
| **M1：能发** | P0 全部 | ~6.5 人日 | 有声、配音/BGM/字幕齐全、可直接发布的短片 |
| **M2：好看** | P1 全部 | ~3.5 人日 | 带转场、封面钩子、可调字幕的成片 |
| **M3：可运营** | P2 挑做（建议 P2-1/2/3） | ~3.5 人日 | 自动重试、成本可见、磁盘可控 |
| **M4：上规模** | P3 按需 | 视范围 | 多用户 / 生产部署 / 合规 / 新前端 |

> 建议节奏：**先做完 M1 并真实出一条有声片验证**，再决定是否继续 M2/M3。M4 取决于商业化路径是否落定。

## 5. 贯穿原则与风险

- **默认关闭**：所有新增能力配置项默认 disabled，关闭时行为与当前逐字节一致，保护 ViMax 上游可合并性。
- **复用优先**：TTS/音效复用 `extract_spoken_content`；重试复用 `utils/retry.py`；写锁复用 `SessionIndex._locked`。
- **新增依赖**：TTS provider SDK、音频处理（ffmpeg 已随 imageio-ffmpeg 自带，`amix/loudnorm` 无需额外二进制）。引入前评估体积与许可证。
- **测试**：每阶段补单测，沿用 unittest 风格，从 SceneForge 根 `.venv/Scripts/python.exe -m pytest` 运行。
- **风险**：
  - 配音音色/自然度依赖所选 TTS provider，需先打样选型（中文情感 TTS 质量差异大）。
  - BGM 素材版权——商用需确认授权来源。
  - 音画对齐：TTS 时长可能超过镜头时长，需定策略（拉长镜头停留 / 压缩语速 / 裁切台词）。
