# SceneForge 消息审核工作流与固定角色设计方案

> 文档状态：个人创作自动化的历史技术设计。本文中的消息审核指同一创作者通过不同入口控制任务，不代表当前支持多人账号、项目成员权限或外部审核。未来多人协作以 `docs/多人协作产品规划.md` 为准。

## 1. 目标

本方案将 SceneForge 从一次性视频生成流水线优化为消息驱动、分阶段审核、可恢复、可配置中文化、支持固定角色资产的视频生产智能体。

目标能力：

- 用户通过微信、飞书或控制台提交视频主题。
- 系统提取或规划角色，并匹配固定角色资产库。
- 用户先审核角色设定，再审核剧本、分镜脚本、分镜视频。
- 用户可在任意审核阶段提出修改意见。
- 系统支持单镜头重生成，而不是默认重跑全片。
- Agent 角色设定和提示词迁移到可编辑 Markdown 文件。
- 默认启用中文口语源文本和中文字幕，可通过配置关闭。
- 最终成片托管后通过消息管道回传链接。

## 4. 用户操作入口

控制台和消息管道都支持，但必须共用同一套命令层，避免两套入口产生不同状态行为。

统一命令模型：

```python
class UserCommand(BaseModel):
    command_type: Literal[
        "new_topic",
        "approve",
        "revise",
        "regenerate",
        "status",
        "pause",
        "resume",
        "cancel"
    ]
    session_id: str | None
    stage: str | None
    text: str | None
    source: MessageSource
```

消息示例：

```text
做一个关于“AI 老师进山村”的公益短片
通过
修改：主角改成女老师，结尾更温暖
重生成第 4 镜，人物表情太僵
查看状态
```

控制台示例：

```bash
sceneforge service start
sceneforge session list
sceneforge session status <session_id>
sceneforge approve <session_id> script
sceneforge revise <session_id> storyboard --text "第 3 镜改成远景"
sceneforge regenerate-shot <session_id> --shot-id 4
```

状态转换示例：

| 当前状态 | 用户指令 | 下一步 |
|---|---|---|
| `character_review_pending` | `通过` | 生成剧本 |
| `character_review_pending` | `替换 林老师=teacher_lin_v2` | 更新角色绑定并重新发起角色审核 |

## 6. 消息通道

新增目录：

```text
channels/
  base.py
  feishu.py
  wechat.py
  console.py
  dispatcher.py
```

统一接口：

```python
class MessagingChannel:
    async def send_text(self, target, text): ...
    async def send_review(self, target, review_task): ...
    async def send_artifact(self, target, artifact): ...
    async def receive(self): ...
```

优先级建议：

- 第一优先实现飞书，官方 API 稳定，适合审核卡片、文件链接和机器人消息。
- 微信作为插件式通道接入。个人微信存在合规和稳定性风险，建议默认关闭。

配置示例：

```yaml
messaging:
  inbound_enabled: true
  outbound_enabled: true
  channels:
    - type: feishu
      enabled: true
      app_id: ${FEISHU_APP_ID}
      app_secret: ${FEISHU_APP_SECRET}
    - type: wechat
      enabled: false
      adapter: personal_wechat
```

## 9. Character Asset Manager

新增模块：

```text
characters/
  asset_manager.py
  matcher.py
  registry.py
  models.py
  render_3d.py
```

职责：

- 读取固定角色资产库。
- 根据主题、剧本、角色描述提取角色需求。
- 根据名字、别名、描述相似度匹配已有角色。
- 没匹配到时创建待生成角色。
- 将固定角色资产注入图像和视频生成流程。
- 记录每个 session 的角色绑定关系。

核心模型：

```python
class CharacterAsset(BaseModel):
    asset_id: str
    display_name: str
    aliases: list[str]
    type: Literal[
        "reference_images",
        "lora",
        "three_d_model",
        "provider_character_id"
    ]
    description: str
    visual_prompt: str | None
    assets: dict[str, str] = {}
    provider: str | None = None
    model_id: str | None = None
    trigger_words: list[str] = []
```

Session 中保存角色绑定：

```json
{
  "characters": [
    {
      "character_id": "char_001",
      "name": "林老师",
      "role": "主角",
      "asset_id": "teacher_lin",
      "asset_type": "reference_images",
      "locked": true,
      "user_approved": true
    }
  ]
}
```

## 10. 角色资产注入生成链路

当前 SceneForge 已有 `character_portraits_registry` 概念，可扩展为正式的 `CharacterAssetRegistry`。

现有逻辑：

```text
CharacterInScene -> 生成 front / side / back portraits -> registry
```

优化后：

```text
CharacterInScene
  -> 查 session character binding
  -> 如果绑定 fixed reference_images
       直接使用固定角色图片
  -> 如果绑定 lora
       给 image generator 注入 lora trigger / model_id
  -> 如果绑定 provider_character_id
       给 video generator 注入 character_ref
  -> 如果没有绑定
       自动生成 front / side / back 并保存为 session 临时资产
```

图像生成接口扩展：

```python
generate_single_image(
    prompt=prompt,
    reference_image_paths=[
        fixed_character.front,
        fixed_character.side,
        fixed_character.expression
    ],
    character_refs=[
        {"character_id": "char_001", "asset_id": "teacher_lin"}
    ],
)
```

视频生成接口扩展：

```python
generate_single_video(
    prompt=motion_prompt,
    reference_image_paths=[first_frame, last_frame],
    character_refs=[
        {"character_id": "char_001", "asset_id": "teacher_lin"}
    ],
)
```

如果底层视频模型不支持 `character_refs`，则退化为：

```text
固定角色参考图 -> 首帧 / 尾帧生成 -> 视频模型参考首尾帧
```

## 11. Pipeline 阶段化

当前 pipeline 需要拆成可暂停、可恢复的阶段函数。

```python
class ProductionPipeline:
    async def plan_characters_from_topic(...)
    async def bind_character_assets(...)
    async def generate_script_from_topic(...)
    async def revise_script(...)
    async def generate_storyboard_from_script(...)
    async def revise_storyboard(...)
    async def generate_shot_descriptions(...)
    async def generate_shot_videos(...)
    async def regenerate_shot_video(...)
    async def assemble_final_video(...)
```

每一步要求：

- 输入明确。
- 输出版本化 artifact。
- 可重复执行。
- 不覆盖旧版本。
- 出错可标记到 session。
- 可从中间状态恢复。

- 支持热更新，用户改 md 后下次运行生效。


```text

```

## 14. 中文配置与中文字幕

配置示例：

```yaml
language:
  chinese_mode: true
  spoken_content_language: zh-CN
  visual_description_language: en

subtitle:
  enabled: true
  burn_in: true
  font_path:
  fallback_fonts:
    - Microsoft YaHei
    - SimHei
    - Noto Sans CJK SC
  style:
    position: bottom
    font_size: 42
    primary_color: white
    outline_color: black
    outline_width: 2
```

中文模式启用时：

- 剧本台词、旁白、独白必须为简体中文。
- `audio_desc` 中 `[Speaker]`、`[Sound Effect]` 等结构保留。
- 视觉描述保持英文，利于图像和视频模型。
- `motion_desc` 中如包含台词，也必须为中文。
- 即使用户改了 md 提示词，也注入独立的 `chinese_runtime_instruction`。

运行时中文约束示例：

```text
中文模式已启用：
- 所有台词、旁白、独白必须使用简体中文。
- 视觉描述、镜头语言、构图、动作描述保持英文。
- audio_desc 中的 [Speaker]、[Sound Effect] 标签保持英文结构。
- 不得用整句英文承载 Spoken_Content。
```

## 15. 字幕服务

新增 `SubtitleService`：

```python
class SubtitleService:
    def extract_spoken_content(shot_description) -> list[SubtitleLine]
    def build_timeline(shot_videos, subtitle_lines) -> SubtitleTrack
    def render_ass(track, style) -> Path
    def burn_in(video_path, subtitle_path) -> Path
```

字幕规则：

- 优先从结构化 `audio_desc` 提取。
- 其次从 `motion_desc` 中提取引号台词或旁白。
- 音效 `[Sound Effect]` 不生成字幕。
- 一个镜头多句台词拆成多条字幕。
- 获取每个 shot video 的实际时长。
- 字幕只出现在对应镜头时间范围内。
- 多条台词按顺序均分或按文本长度分配时间。

烧录方案：

- 推荐生成 `.ass` 字幕，再用 ffmpeg 或 moviepy 烧录。
- 如果找不到中文字体，记录诊断，继续产出无字幕视频。
- 可保留 `.srt` 作为调试产物，最终交付以硬字幕视频为主。

## 16. 角色固定与用户修改冲突处理

如果用户反馈涉及固定角色外观，例如：

```text
修改：林老师更年轻一点
```

系统应判断该角色是否已锁定固定资产。

若已锁定，不应直接改变外观，而应回复确认：

```text
林老师当前使用固定角色 teacher_lin。
是否解除固定并重新生成角色？

回复：
解除固定 林老师
保持固定，仅调整性格表现
```

这样可以防止“固定角色”被剧本文案或分镜提示悄悄改掉。

## 17. 成本护栏

配置示例：

```yaml
generation_budget:
  max_characters: 6
  max_new_character_assets: 3
  max_scenes: 3
  max_total_shots: 12
  max_shot_regenerations: 2
  max_paid_calls: 40
  max_wall_clock_minutes: 60
  default_shot_duration_seconds: 5
```

作用点：

- 生成角色后限制主要角色数量。
- 生成剧本后裁剪或重规划场景数量。
- 生成分镜后裁剪镜头数量。
- 视频生成前确认实际 shot 数不超过上限。
- 局部重生成时限制每个 shot 的重试次数。
- 入站消息触发必须经过授权和限频。

角色超过上限时示例：

```text
本次识别到 9 个角色，超过上限 6。
请确认保留哪些主要角色，或允许系统合并次要角色。
```

```yaml
    max_concurrent_sessions: 1
  global:
    max_concurrent_generations: 2
```

要求：

- 未授权消息不触发生成。
- 记录诊断日志。
- 可选回复“无权限”。
- 入站触发必须受预算、授权、限频共同约束。

## 22. 第一版最务实方案

第一版不直接做 LoRA、3D 模型或供应商角色 ID。

建议第一版固定角色定义为：

```text
固定角色 = 多角度参考图 + 角色描述 + 别名匹配 + 用户审核锁定
```

原因：

- 与当前 SceneForge 的 `front / side / back` 画像机制最兼容。
- 现有首帧、尾帧生成已经支持参考图。
- 不需要更换底层视频模型。
- 能最快提升人物一致性。

后续扩展路线：

```text
reference_images -> LoRA -> provider_character_id -> 3D model
```

## 23. 结论

加入固定角色后，SceneForge 的核心能力应从“根据文字生成视频”升级为：

```text
围绕固定角色 IP，使用消息驱动和人工审核闸门，持续生产一致性更高、可控性更强的视频内容。
```

关键新增能力：

- `Workflow Engine` 保证流程正确。
- `Review Manager` 支持分阶段人工审核。
- `Character Asset Manager` 管理固定角色和角色绑定。
- `Prompt Manager` 支持 md 角色设定和提示词外置。
- `Subtitle Service` 支持默认中文字幕。
- `Budget Guard` 防止无人值守生成失控。
- `Channel Dispatcher` 打通飞书、微信和控制台入口。
