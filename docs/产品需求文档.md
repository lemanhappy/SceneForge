# 产品需求文档

（中文需求文档：可编辑提示词、默认中文配音/字幕、消息渠道分发与触发，含成本护栏与非功能需求）

> 本版基于对**当前代码**与**一次完整端到端实跑**的核验修订，修正了若干与真实实现不符或不可验收的描述，并补充了成本、触发服务、鉴权、托管与编码健壮性等缺失需求。

## Introduction

SceneForge 是一个多智能体视频生成流水线，能把一个创意或剧本转化为成片 `final_video.mp4`。整条流水线依次经过：故事开发、角色提取、剧本撰写、分镜设计、镜头拆解、首/尾帧图像生成、逐镜头视频片段生成、场景级与全局拼接。其中**剧本、分镜、镜头等内容由 LLM 实时自动生成**；真正写死在代码里的是各 Agent 的**系统/人类提示词（角色设定与任务指令）**，它们以 Python 三引号字符串常量内联在 `agents/*.py` 中，且单个 Agent 往往含**多条**提示词（如编剧含"故事开发""剧本撰写"两套，分镜师含"分镜设计""视觉拆解"两套）。这些提示词目前没有任何外部化配置层，用户无法在不改代码的情况下调整 Agent 行为。

经实跑核验的若干关键事实（构成本规格的前提）：

- **配音由视频模型合成，SceneForge 不做 TTS**：每个镜头的 `audio_desc` 文本随 `motion_desc` 一并作为 prompt 交给视频生成模型（如 Seedance/Veo），由模型自行合成语音。SceneForge 既不生成也不持有独立音轨，**无法逐字控制实际念出的内容与时序**。
- **当前无任何字幕能力**，生成内容语言"跟随输入语言"。
- **成片是本地文件**（`working_dir/.../final_video.mp4`）；单镜头视频在中间步骤可能有第三方临时 URL，但最终拼接片仅本地存在，**无任何外部分发能力**。
- **LLM 不一定遵守镜头/场景数约束**：即便在 `user_requirement` 中限制镜头数，模型也可能大幅超出（实跑中"每场景≤2镜头"被生成为单场景 11 镜头），直接放大耗时与付费调用成本。
- **存在两套独立提示词体系**：`agents/*.py`（流水线 Agent，本规格模块 A 的对象）与 `prompts/*.md` + `PromptBuilder`（TUI Agent Loop，已是外置 md，**不在**模块 A 范围内）。

本规格定义四块能力，并统一输出为一份需求文档：

1. **可编辑的外置提示词（基础能力）**：把流水线各 Agent 的提示词从代码搬到用户可编辑的 Markdown 文件，运行时从 md 加载并安全填充占位符。
2. **默认中文配音 + 中文字幕**：让简体中文配音（台词/独白/旁白）与烧录式简体中文字幕成为默认行为，可通过配置开关关闭。
3. **消息渠道分发与触发**：支持**出站分发**（成片回送渠道）与**入站触发**（在个人微信/飞书发主题触发生成），含成片托管、常驻触发服务与来源鉴权。
4. **生成规模与成本护栏**：对 LLM 产出的场景/镜头规模施加硬上限，约束单次生成的耗时与付费调用量，保护"消息触发"等无人值守场景。

本文件只定义**需求**。具体实现选择（md 目录结构、加载机制、字幕库、字体查找、托管方案、各渠道 API/Webhook、服务形态等）留到设计阶段。

## 模块依赖与实现顺序

- **B 依赖 A**：中文模式的"强制中文配音/字幕指令"通过模块 A 的提示词默认内容承载；若 A 的兜底回退到内置默认，必须保证中文约束仍然生效（见 B7），不得因 md 被改回而静默失效。
- **C 依赖 D**：入站触发属无人值守付费生成，必须受模块 D 的硬上限与模块 C 的鉴权/限频共同约束后方可启用。
- 建议实现顺序：**A → D → B → C**。

## Glossary

- **SceneForge**：本规格覆盖的整个多智能体视频生成系统。
- **Idea2Video_Pipeline / Script2Video_Pipeline**：分别是创意到视频、剧本到视频的入口流水线。
- **Agent**：流水线中承担单一职责的智能体（编剧、分镜师、镜头拆解、角色提取、参考图选择、镜头图像生成等）。
- **Prompt_Unit（提示词单元）**：驱动某个 Agent 某一步行为的、可独立寻址的一条提示词文本（区分 system/human、区分同一 Agent 内的不同任务）。**外置以 Prompt_Unit 为粒度，而非以 Agent 为粒度**。
- **Prompt_File（提示词文件）**：本功能引入的、承载某个 Prompt_Unit 的可编辑 Markdown 文件。
- **Prompt_Placeholder（提示词占位符）**：Prompt_Unit 中需运行时填充的具名变量（如 `{format_instructions}`、`{idea}`、`{user_requirement}`、`{visual_desc}` 等）。
- **Placeholder_Set（占位符集合）**：某个 Prompt_Unit 在迁移时声明的、其必需占位符的固定集合，用于加载时校验与安全填充。
- **Spoken_Content（口语内容）**：镜头中所有应被念出的人声文本（台词、独白、画外音、旁白），承载于 `audio_desc` 及 `motion_desc` 内嵌的引号台词/旁白。**注意：这是"期望念出"的源文本，不等于视频模型实际合成的语音。**
- **Visual_Description（视觉描述）**：描述构图、镜头、光照、角色外观与运动的文本（`visual_desc`、`ff_desc`、`lf_desc` 及 `motion_desc` 的非台词部分），由图像/视频模型消费。
- **Audio_Desc**：逐镜头 `audio_desc` 字段，语音格式为 `[Speaker] <名字> (<情绪>): <台词>`，非语音格式为 `[Sound Effect] ...`；单镜头可含多条。
- **Subtitle_Generator（字幕生成器）**：本功能引入的组件，从每个镜头的 Spoken_Content 推导字幕文本与时间轴并烧录到视频。
- **Burned_In_Subtitle（烧录/硬字幕）**：直接渲染进视频画面的字幕。
- **Shot_Clip（镜头片段）**：拼接前的逐镜头视频文件（`shots/{idx}/video.mp4`）。
- **Chinese_Language_Mode（中文模式）**：可配置模式，启用后强制 Spoken_Content 为简体中文并启用中文 Burned_In_Subtitle。
- **Chinese_Font（中文字体）**：能渲染简体中文字形的字体文件。
- **Messaging_Channel（消息渠道）**：可接收成片分发、并可作为生成触发入口的外部消息平台（本期为个人微信、飞书），可扩展。
- **Delivery（出站分发）**：把成片引用及其基本信息发送到一个或多个 Messaging_Channel 的动作。
- **Inbound_Trigger（入站触发）**：从某个 Messaging_Channel 接收用户发送的主题消息、据此触发一次视频生成的能力。
- **Trigger_Service（触发服务）**：为承载 Inbound_Trigger 而引入的、可长期运行并监听渠道消息的常驻进程/服务。
- **Authorized_Source（授权来源）**：被 Config 显式允许触发生成的消息来源（用户/群/账号）。
- **Generation_Request（生成请求）**：由一条 Inbound_Trigger 消息解析出的、用于驱动一次生成的输入（至少含主题文本）。
- **Hosting_Location（托管位置）**：成片被放置、从而可由收件人通过链接访问的位置（对象存储/可达地址等）。
- **Generation_Budget（生成预算）**：单次生成允许消耗的上限集合，至少包含场景数上限、镜头总数上限，可含付费调用次数/时长上限。
- **Config（配置）**：初始化流水线所用的 YAML 配置文件。

## Requirements

---
### 模块 A：可编辑的外置 Agent 提示词

> 范围：仅覆盖 `agents/*.py` 中内联的流水线提示词；TUI 的 `prompts/*.md`（已外置）不在本模块范围内。

#### 需求 A1：提示词以 Prompt_Unit 粒度外置到可编辑 Markdown

**用户故事：** 作为 SceneForge 用户，我希望每一条 Agent 提示词都放在可编辑的 md 文件里，这样我无需改代码就能调整任意一步的行为。

##### 验收标准

1. THE SceneForge SHALL 把每个 Prompt_Unit 存放在一个独立的、用户可编辑的 Prompt_File 中（同一 Agent 的多条提示词分别对应各自的 Prompt_File）。
2. THE SceneForge SHALL 在运行各 Agent 的对应步骤时，从其 Prompt_File 加载 Prompt_Unit，而不再使用内联在代码中的字符串常量。
3. WHEN 用户在不修改任何代码的情况下编辑某个 Prompt_File 并重新运行流水线，THE SceneForge SHALL 使用编辑后的内容。
4. THE SceneForge SHALL 为每个 Prompt_File 提供默认内容，且该默认内容**逐字等于**迁移时从原 `agents/*.py` 抽取的对应提示词文本（一次性抽取，保证字节级一致，从而可自动比对验收）。

#### 需求 A2：占位符的保留与安全填充

**用户故事：** 作为 SceneForge 用户，我希望编辑提示词时其中的变量仍被正确填充、且即使我误写花括号也不会让流水线崩，这样改动提示词是安全的。

##### 验收标准

1. THE Prompt_File SHALL 以可识别形式保留其 Placeholder_Set 中的每个 Prompt_Placeholder。
2. WHEN SceneForge 从 Prompt_File 加载并执行某 Prompt_Unit，THE SceneForge SHALL **仅替换 Placeholder_Set 中声明的占位符**，并对其余字面文本（含任意 `{`、`}` 字面花括号、JSON 示例）原样保留，不得因此抛错。
3. IF 某个 Prompt_File 缺少其 Placeholder_Set 要求的占位符，THEN THE SceneForge SHALL 记录一条指明缺失占位符与所属 Prompt_File 的诊断信息。
4. IF 某个 Prompt_File 含 Placeholder_Set 之外的未知具名占位符，THEN THE SceneForge SHALL 将其按字面保留，并记录一条提示其未被填充的诊断信息（而非崩溃）。

#### 需求 A3：缺失、损坏或填充失败时的兜底

**用户故事：** 作为 SceneForge 用户，我希望提示词文件丢失、写坏或填充出错时流水线不崩，这样运行更稳健。

##### 验收标准

1. IF 某个 Prompt_Unit 的 Prompt_File 不存在，THEN THE SceneForge SHALL 使用其内置默认提示词继续运行，并记录一条诊断信息。
2. IF 某个 Prompt_File 无法被读取或解析，THEN THE SceneForge SHALL 记录一条指明该 Prompt_File 的诊断信息，并使用内置默认提示词继续运行。
3. IF 从某个 Prompt_File 加载后**占位符填充失败**（如缺必需占位符导致无法构造有效提示词），THEN THE SceneForge SHALL 记录一条指明 Prompt_File 与失败原因的诊断信息，并回退到内置默认提示词继续运行。

### 模块 B：默认中文配音 + 中文字幕

> 重要前提：配音由视频模型按提示文本自行合成，SceneForge 无法保证模型实际念出的语言、用词与时序（见"非目标与已知风险"）。本模块约束的是**交给模型的源文本**与**基于源文本烧录的字幕**，而非模型合成结果本身。

#### 需求 B1：中文模式为默认

**用户故事：** 作为 SceneForge 用户，我希望中文配音与中文字幕对每个新视频都是默认，这样不必每次重配。

##### 验收标准

1. WHERE 未提供任何语言配置，THE SceneForge SHALL 在 Chinese_Language_Mode 启用状态下运行。
2. THE SceneForge SHALL 对 Idea2Video_Pipeline 与 Script2Video_Pipeline 同等地应用 Chinese_Language_Mode。
3. WHERE Chinese_Language_Mode 启用，THE SceneForge SHALL 将本次运行每个镜头的 Spoken_Content（源文本）强制为简体中文。
4. WHERE Chinese_Language_Mode 启用，THE SceneForge SHALL 基于该源文本产出含中文 Burned_In_Subtitle 的成片。
5. WHERE Config 将该开关设为关闭，THE SceneForge SHALL 按原有"跟随输入语言"行为生成 Spoken_Content 与字幕。

#### 需求 B2：所有口语内容的中文源文本（可自动验收）

**用户故事：** 作为 SceneForge 用户，我希望所有台词、独白、旁白的源文本都是简体中文，这样配音与字幕的依据是中文。

##### 验收标准

1. WHERE Chinese_Language_Mode 启用，WHEN SceneForge 生成某镜头 Audio_Desc，THE SceneForge SHALL 以简体中文表达其 Spoken_Content。
2. WHERE Chinese_Language_Mode 启用，WHEN SceneForge 在 `motion_desc` 中内嵌台词或旁白，THE SceneForge SHALL 以简体中文表达之。
3. WHERE Chinese_Language_Mode 启用，THE SceneForge SHALL 保持每个镜头的 Visual_Description 为英文。
4. WHERE Chinese_Language_Mode 启用，THE SceneForge SHALL 保留 Audio_Desc 的非口语结构标记（`[Speaker]`、说话人名字、`[Sound Effect]` 等），仅令其中 Spoken_Content 为中文。
5. WHERE Chinese_Language_Mode 启用，WHEN 某镜头不含 Spoken_Content，THE SceneForge SHALL 保持非语音 Audio_Desc 不变。
6. **可验收判据：** WHERE Chinese_Language_Mode 启用，THE 每条 Spoken_Content SHALL 至少包含一个中日韩统一表意文字，且不以成句拉丁文本承载台词（专有名词、缩写除外）；该判据可由自动检测施加。

#### 需求 B3：从口语内容生成中文字幕（支持单镜头多条台词）

**用户故事：** 作为 SceneForge 用户，我希望字幕文本来源于每个镜头的口语内容，且一个镜头里的多句台词都能成为字幕。

##### 验收标准

1. WHERE Chinese_Language_Mode 启用，WHEN 某镜头含 Spoken_Content，THE Subtitle_Generator SHALL 提取其口语台词作为该镜头的中文字幕文本。
2. WHERE 某镜头含**多条** Spoken_Content，THE Subtitle_Generator SHALL 将其拆分为多条按出现顺序排列的字幕条目。
3. WHERE Chinese_Language_Mode 启用，THE Subtitle_Generator SHALL 从字幕文本中排除结构标记与说话人名字（`[Speaker]`、情绪标注等）。
4. WHERE 某镜头 Spoken_Content 缺失或为空，THE Subtitle_Generator SHALL 不为该镜头渲染字幕。
5. WHERE 某镜头仅含音效等非语音音频，THE Subtitle_Generator SHALL 不为该镜头渲染字幕。

#### 需求 B4：逐镜头的字幕时间轴

**用户故事：** 作为 SceneForge 用户，我希望每个镜头的字幕只在该镜头期间出现，这样字幕与片段对齐。

##### 验收标准

1. WHERE Chinese_Language_Mode 启用，THE Subtitle_Generator SHALL 根据对应 Shot_Clip 的**实测时长**推导该镜头字幕的时间轴。
2. WHERE 某镜头含多条字幕，THE Subtitle_Generator SHALL 在该 Shot_Clip 时长内按比例/顺序为各条目分配不重叠的显示区间。
3. WHERE Chinese_Language_Mode 启用，WHEN Subtitle_Generator 渲染某镜头字幕，THE Subtitle_Generator SHALL 将其显示区间限制在该 Shot_Clip 时长之内。
4. WHEN 各镜头拼接为成片，THE SceneForge SHALL 在成片时间轴中保持每条字幕处于其所属镜头的位置。

#### 需求 B5：烧录字幕并兜底字体

**用户故事：** 作为 SceneForge 用户，我希望字幕烧进视频且在缺字体时不崩。

##### 验收标准

1. WHERE Chinese_Language_Mode 启用，THE SceneForge SHALL 将中文字幕作为 Burned_In_Subtitle 渲染进输出视频，并输出到本次运行既有的 `final_video.mp4` 位置。
2. WHERE 存在可用的 Chinese_Font，THE SceneForge SHALL 使用该 Chinese_Font 渲染 Burned_In_Subtitle。
3. IF 启用中文模式时无可用 Chinese_Font，THEN THE SceneForge SHALL 记录一条指明缺失字体的诊断信息，并完成本次运行、产出不含 Burned_In_Subtitle 的成片。

#### 需求 B6：中文行为的配置开关

**用户故事：** 作为 SceneForge 运维者，我希望有一个统一开关控制中文行为，无需改代码即可关闭。

##### 验收标准

1. THE SceneForge SHALL 从 Config 读取 Chinese_Language_Mode 开关。
2. WHERE Config 缺少该开关，THE SceneForge SHALL 默认其为启用。
3. WHERE 该开关关闭，THE SceneForge SHALL 跳过 Burned_In_Subtitle 生成，并按原有"跟随输入语言"行为生成 Spoken_Content。

#### 需求 B7：中文约束不依赖可被改回的提示词（B 对 A 的依赖加固）

**用户故事：** 作为 SceneForge 用户，我希望即使提示词 md 被改动或回退默认，中文模式仍然生效，这样中文行为是可靠的。

##### 验收标准

1. WHERE Chinese_Language_Mode 启用，IF 模块 A 因任何兜底而使用内置默认提示词，THEN THE SceneForge SHALL 仍对 Spoken_Content 施加中文约束（如通过独立于可编辑 md 的运行时指令注入）。
2. THE SceneForge SHALL 使 B2 的可验收判据在"提示词处于默认态"与"提示词被用户编辑"两种情况下均成立。

---
### 模块 C：消息渠道分发与触发（个人微信、飞书等）

> 本模块覆盖**出站分发**、**入站触发**、**成片托管**与**触发服务/鉴权**。渠道本期为**个人微信**与**飞书**，可扩展。入站触发须在模块 D 与本模块鉴权/限频约束下方可启用。

#### 需求 C1：成片分发到消息渠道

**用户故事：** 作为 SceneForge 用户，我希望成片生成后自动推送到我的渠道，无需手动到工作目录找文件。

##### 验收标准

1. WHEN 一次运行成功产出成片，WHERE 分发已在 Config 启用，THE SceneForge SHALL 将该成片分发到每个已配置的 Messaging_Channel。
2. THE SceneForge SHALL 在每次分发中包含成片引用及其基本信息（至少含故事标题与一段简短摘要）。
3. WHERE 配置了多个 Messaging_Channel，THE SceneForge SHALL 向其中每一个进行分发。

#### 需求 C2：支持个人微信与飞书且可扩展

##### 验收标准

1. THE SceneForge SHALL 支持把成片分发到个人微信。
2. THE SceneForge SHALL 支持把成片分发到飞书。
3. THE SceneForge SHALL 允许在不修改既有渠道实现的前提下新增其它 Messaging_Channel 类型。
4. WHEN 向任一 Messaging_Channel 分发成片，THE SceneForge SHALL 发送一个指向该成片的可访问链接，并附带其基本信息（标题与简短摘要）。

#### 需求 C3：成片托管与可访问链接（由原"待确认假设1"升格）

**用户故事：** 作为 SceneForge 用户，我希望分发的链接对方真的能打开，这样"发链接"才有意义。

##### 验收标准

1. WHEN 需要以链接形式分发成片，THE SceneForge SHALL 将本地 `final_video.mp4` 放置到一个 Hosting_Location，并据此生成对收件人可访问的链接。
2. THE SceneForge SHALL 从 Config 读取 Hosting_Location 的接入参数。
3. IF 托管或生成链接失败，THEN THE SceneForge SHALL 记录诊断信息，并按 C5 的失败策略处理（不影响成片产出本身）。
4. WHERE 未配置任何 Hosting_Location 且分发要求链接形式，THE SceneForge SHALL 跳过该渠道分发并记录诊断信息，而非发送不可访问的链接。

#### 需求 C4：渠道凭据来自配置且默认关闭

##### 验收标准

1. THE SceneForge SHALL 从 Config 读取每个 Messaging_Channel 的接入参数（Webhook/凭据等）。
2. WHERE 未启用分发或未配置任何 Messaging_Channel，THE SceneForge SHALL 跳过分发并照常完成成片产出。
3. THE SceneForge SHALL 不把渠道凭据与 Hosting_Location 凭据明文输出到日志。

#### 需求 C5：分发失败不影响成片产出

##### 验收标准

1. IF 向某个 Messaging_Channel 的分发失败，THEN THE SceneForge SHALL 记录指明渠道与原因的诊断信息，并视该次成片产出为成功。
2. IF 向某渠道分发失败 WHERE 配置了多个渠道，THEN THE SceneForge SHALL 仍尝试向其余渠道分发。

#### 需求 C6：常驻触发服务

**用户故事：** 作为 SceneForge 用户，我希望有一个能一直运行、监听渠道消息的服务，这样我离开电脑也能用发消息的方式发起生成。

##### 验收标准

1. WHERE 入站触发已在 Config 启用，THE SceneForge SHALL 提供一个 Trigger_Service，能长期运行并监听已配置渠道的入站消息。
2. WHERE 入站触发未在 Config 启用，THE Trigger_Service SHALL 不监听任何渠道。
3. THE 既有一次性 CLI 入口（`main_idea2video.py` / `main_script2video.py`）SHALL 保持可独立使用，不因引入 Trigger_Service 而失效。
4. IF Trigger_Service 在处理某条消息时发生未捕获错误，THEN THE Trigger_Service SHALL 记录诊断信息并继续监听后续消息，而非整体退出。

#### 需求 C7：入站触发的来源鉴权与限频（安全/成本）

**用户故事：** 作为 SceneForge 运维者，我希望只有被授权的人能用发消息触发生成、且有频率与并发限制，这样不会被人刷爆、烧光额度。

##### 验收标准

1. WHEN 某渠道收到入站消息，THE SceneForge SHALL 仅在该来源属于 Config 中的 Authorized_Source 时受理为 Generation_Request；否则忽略并记录诊断信息。
2. THE SceneForge SHALL 从 Config 读取每来源/全局的触发频率上限与并发上限，并在超限时拒绝新的触发、向来源回送已限流的提示。
3. THE SceneForge SHALL 使每一次由入站触发发起的生成都受模块 D 的 Generation_Budget 约束。

#### 需求 C8：从消息渠道入站触发生成

**用户故事：** 作为 SceneForge 用户，我希望在个人微信或飞书发一个主题就能触发生成。

##### 验收标准

1. WHERE 入站触发已启用 AND 来源为 Authorized_Source，WHEN 某渠道收到一条主题消息，THE SceneForge SHALL 从中解析出 Generation_Request。
2. WHEN 得到 Generation_Request，THE SceneForge SHALL 以该主题为输入发起一次（受 D 约束的）视频生成。
3. WHEN SceneForge 受理一条 Inbound_Trigger，THE SceneForge SHALL 向来源回送一条已受理的确认信息。
4. WHEN 由 Inbound_Trigger 发起的生成成功产出成片，THE SceneForge SHALL 按 C1–C5 把成片回送到发起请求的来源渠道。
5. IF 一条入站消息无法解析为有效 Generation_Request，THEN THE SceneForge SHALL 向来源回送说明无法处理的信息，且不发起生成。

### 模块 D：生成规模与成本护栏

> 动机：LLM 不保证遵守镜头/场景数约束，单次生成的付费调用量与耗时可能失控；对无人值守的入站触发尤其危险。本模块用**硬上限**兜底，不依赖 LLM 自觉。

#### 需求 D1：场景与镜头数的硬上限

**用户故事：** 作为 SceneForge 用户，我希望无论 LLM 怎么发挥，单次生成的场景数和镜头总数都不会超过我设定的上限，这样成本可预期。

##### 验收标准

1. THE SceneForge SHALL 从 Config 读取 Generation_Budget（至少含场景数上限与镜头总数上限）。
2. WHERE Config 未提供上限，THE SceneForge SHALL 采用一组有界的安全默认值（而非无上限）。
3. WHEN 分镜/镜头规划产出的场景数或镜头总数超过相应上限，THE SceneForge SHALL 在进入付费的图像/视频生成**之前**将其裁剪或重规划至不超过上限，并记录一条说明被裁剪规模的诊断信息。
4. THE SceneForge SHALL 保证实际进入视频生成阶段的 Shot_Clip 数量不超过镜头总数上限。

#### 需求 D2：付费调用与时长的可选上限

##### 验收标准

1. WHERE Config 配置了单次生成的付费调用次数上限或墙钟时长上限，THE SceneForge SHALL 在达到上限时停止发起新的付费生成调用，并以"部分完成 + 诊断信息"的方式结束本次运行。
2. WHERE 未配置此类上限，THE SceneForge SHALL 至少应用 D1 的规模上限。

### 非功能需求（NFR）

#### 需求 N1：编码与跨平台健壮性（UTF-8 / Windows）

**用户故事：** 作为在中文 Windows 上运行的用户，我希望全链路对中文与 emoji 不崩，这样中文化功能可用。

##### 验收标准

1. THE SceneForge SHALL 以 UTF-8 读写所有文本文件（配置、提示词 md、中间产物 JSON、字幕等），不依赖操作系统区域编码。
2. THE SceneForge SHALL 使进度/日志输出在中文 Windows 控制台（如 GBK 代码页）下不因中文或 emoji 触发编码错误。
3. THE SceneForge SHALL 使所有出网调用（含基于 aiohttp 的图像/视频工具）使用可用的 CA 证书完成 TLS 校验，不因缺省证书链在 Windows 上失败。
4. THE 三块新功能（A/B/C）SHALL 在 Linux 与 Windows 上行为一致。

#### 需求 N2：诊断信息的可观测性与脱敏

##### 验收标准

1. THE SceneForge SHALL 使本规格各处要求的"诊断信息"可被用户在运行日志中看到，并指明涉及的文件/渠道/规模等定位信息。
2. THE SceneForge SHALL 不在任何诊断信息中明文输出凭据（LLM/图像/视频 API key、渠道凭据、Hosting 凭据）。

## 已确认决策

1. **方向**：出站分发与入站触发**两者都做**。
2. **微信形态**：使用**个人微信**作为渠道（接收主题、回送链接）；鉴于合规风险，设计阶段可推荐企业微信/飞书为更稳方案。
3. **分发内容形态**：以"**可访问链接 + 标题/摘要**"发送成片（不强制直接发原文件）。
4. **范围**：模块 A（提示词外置）、B（中文配音/字幕）、C（渠道分发与触发）、D（成本护栏）**本期一次性全做**。
5. **提示词外置粒度**：以 **Prompt_Unit** 为粒度，而非 Agent。
6. **成片托管**：纳入正式需求（C3），具体托管方案设计阶段定。

## 非目标与已知风险

- **配音内容与字幕可能不一致（升级风险）**：配音由第三方视频模型按提示文本自行合成，**不仅时序不保证逐字对齐，实际念出的用词、语言乃至是否有清晰人声都可能偏离源文本**。字幕以 SceneForge 的源文本为准，不保证与模型实际语音匹配。
- **中文语音质量**：中文配音的质量、口音、发音取决于第三方视频模型，超出 SceneForge 控制范围。
- **字幕样式配置**：除清晰可读所必需者外，细粒度样式（字号、颜色、位置、描边）不在范围内。
- **简体中文以外的语言**：本功能仅覆盖简体中文；通用多语言系统不在范围内。
- **外挂字幕文件**：不产出独立 `.srt` 等旁挂字幕文件；字幕烧录进视频。
- **提示词语义校验**：保证从 md 加载并安全填充占位符，但不校验用户改写后提示词是否"合理"；改坏导致的质量下降由用户负责。
- **裁剪带来的叙事影响**：模块 D 的硬上限可能截断 LLM 规划的剧情；本规格优先保证成本可控，叙事完整性让位于上限。
- **消息平台合规与配额**：微信/飞书的接口配额、审核、机器人权限、文件大小限制等由平台决定，超出 SceneForge 控制范围。
- **个人微信无官方开放接口（重要风险）**：个人微信没有官方对外 API，接入通常依赖非官方手段（hook/网页协议/第三方库），存在违反使用条款、账号被封、随版本失效、稳定性差等风险。其接入方式的可行性、合规性与稳定性需在设计阶段评估，必要时改用企业微信/飞书等更稳妥渠道作为推荐方案。
- **Trigger_Service 的运维形态**：常驻服务的部署、保活、鉴权密钥轮换等运维细节留待设计阶段。
